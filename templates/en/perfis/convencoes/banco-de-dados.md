## Profile conventions: database

### Suggested structure

```text
db/migrations/           # dbmate migrations: YYYYMMDDHHMMSS_description.sql
db/seeds/                # initial and sample data (idempotent)
db/schema.sql            # current schema generated by `dbmate dump` (do not edit by hand)
sql/views/               # views and functions (CREATE OR REPLACE)
sql/reports/             # report queries, one per file, with the requirement ID in the header
sql/loads/               # loads/ETL: staging → validation → final table
tests/                   # pgTAP tests (*.sql)
.sqlfluff                # [sqlfluff] dialect = postgres
```

Quick start: install PostgreSQL and [dbmate](https://github.com/amacneil/dbmate); `pip install sqlfluff`;
in the test database, `CREATE EXTENSION pgtap;` (package `postgresql-<version>-pgtap`) and install `pg_prove` (`cpan TAP::Parser::SourceHandler::pgTAP`).
`DATABASE_URL` in `.env`; `dbmate new <description>`, `dbmate up`, `dbmate rollback`, `dbmate status`.
MySQL: replace `--dialect postgres` with `--dialect mysql` in the commands and test with pytest.

### Patterns

- Names in snake_case, singular tables, PK `id` (`bigint generated always as identity` or `uuid`), FK `<table>_id`,
  indexes `ix_<table>_<columns>`, uniques `uq_...`, checks `ck_...`. Dates `timestamptz` in UTC; money `numeric(12,2)`.
- Every migration has `-- migrate:up` and `-- migrate:down` and runs in a transaction. Never edit an applied migration; create another.
- Incompatible change: expand → migrate data → contract, in separate deploys. On a large table, `CREATE INDEX CONCURRENTLY`
  (outside a transaction: `-- migrate:up transaction:false`) and backfill in batches.
- Constraints in the database (NOT NULL, FK, CHECK, UNIQUE): the business rule the database enforces cites the ID (`-- RN-003`).
- Queries: explicit columns (no `SELECT *` in views and reports), `EXPLAIN (ANALYZE, BUFFERS)` on every critical
  query, recording the result in `06-banco-de-dados.md` (section 5). Keyset pagination (`WHERE id > $1`) on large lists.
- Idempotent loads: natural key + `INSERT ... ON CONFLICT`; rejected rows in a quarantine table with the reason.

### Security

- Separate roles (application without DDL, migration, read-only); never use the superuser in the application or in reports.
- Parameterized queries always; dynamic SQL only with `format('%I', ...)`/`quote_ident`.
- Personal data: the minimum needed, masked in report views; no production dump in a test environment without anonymizing.
- Never run `DROP`, `TRUNCATE` or `DELETE`/`UPDATE` without `WHERE` in production; before touching production, backup and the user's confirmation.

### Tests

- pgTAP per file in `tests/`: `BEGIN; SELECT plan(n); ... SELECT * FROM finish(); ROLLBACK;` (structure with `has_table`/`col_not_null`,
  rules with `throws_ok`, reports with `results_eq`). Test database recreated from scratch with `dbmate up` + seeds.
- Suggested commands: format `sqlfluff format --dialect postgres {arquivo}`, lint `sqlfluff lint --dialect postgres {arquivo}`,
  test `pg_prove -r tests` (connection through the `PGHOST`, `PGDATABASE`, `PGUSER` variables).
